# Implementation Plan: Configurable Hotkeys

## Summary

Add process-lifetime Windows global shortcuts for Close app (F3) and Show settings (F4), plus a Hotkeys page in the existing settings shell for viewing, recording, validating, resetting, and persisting bindings. Keep registration and dispatch in Rust so shortcuts remain active after the WebView settings window is destroyed. Use Tauri's official global-shortcut plugin, transact binding replacements so failed registrations preserve the old working configuration, and extend the existing JSON settings document with backward-compatible hotkey defaults.

## Technical Context

**Language/Version**: TypeScript 7 / ES2022; Rust stable, edition 2024

**Primary Dependencies**: Tauri 2.11, `tauri-plugin-global-shortcut` 2.x, Serde/serde_json, framework-free DOM/CSS

**Storage**: Existing JSON settings file in the per-user Tauri application config directory

**Testing**: Rust unit tests via `cargo test`; TypeScript/build validation via `npm run build`; manual Windows global-shortcut scenarios from `quickstart.md`

**Target Platform**: Windows 10 and 11 desktop (MSVC), matching the current native overlay scope

**Project Type**: Single-process desktop application with a TypeScript WebView settings UI and Rust native runtime

**Performance Goals**: Show/focus Settings within 1 second of a shortcut press; no polling or idle render loop; one action dispatch per physical key press

**Constraints**: Shortcuts must survive Settings WebView destruction; rebind failures must preserve prior working registrations; app remains tray-operable when a saved shortcut is unavailable; no duplicate Settings windows

**Scale/Scope**: Two application actions, one new Settings page, one user's local persisted configuration
